# 과제-08: 최소 비용 신장 트리 알고리즘 비교

## 실험 환경
- 정점 50개, 간선 가중치는 1~100 랜덤인 무방향 단순 그래프 (자기 루프, 중복 간선 없음)
- 희소 그래프: 간선 100개 / 밀집 그래프: 간선 600개
- 연결 그래프를 보장하기 위해 랜덤 신장 트리(간선 49개)를 먼저 만들고 나머지 간선을 추가했으며,
  생성 후 Union-Find로 연결 여부를 다시 확인했다.
- Case 1과 3은 같은 희소 그래프, Case 2와 4는 같은 밀집 그래프를 사용했다.
- Seed: 1792034728
- sizeof(ListNode) = 16, sizeof(AdjList) = 408, sizeof(AdjMatrix) = 10004, sizeof(WEdge) = 12 (64비트 환경)
- 메모리 = 그래프 표현 + 보조 자료구조 + MST 결과 저장 공간(간선 49개)
  - Kruskal 보조 자료구조: 정렬용 간선 배열, Union-Find(parent, rank)
  - Prim 보조 자료구조: key, parent, visited 배열
- 실행시간은 그래프 생성이 끝난 뒤 MST 계산만 측정했고(출력 제외), 한 번 실행하면 너무 짧아서
  10,000번 반복한 평균(us)을 사용했다. Kruskal의 간선 수집, 정렬, Union-Find 초기화도 시간에 포함했다.
  gcc 기본 옵션(최적화 없음)으로 컴파일했으므로 절대 시간보다 케이스 사이의 비교가 의미 있다.

## 측정 결과

| 항목 | Case 1 희소/리스트/Kruskal | Case 2 밀집/리스트/Kruskal | Case 3 희소/행렬/Prim | Case 4 밀집/행렬/Prim |
|---|---|---|---|---|
| MST 간선 수 | 49 | 49 | 49 | 49 |
| MST 전체 비용 | 1493 | 271 | 1493 | 271 |
| 메모리 합계 (Bytes) | 5796 | 27796 | 11192 | 11192 |
| - 그래프 표현 | 3608 | 19608 | 10004 | 10004 |
| - 보조 자료구조 | 1600 | 7600 | 600 | 600 |
| - MST 결과 | 588 | 588 | 588 | 588 |
| 실행시간 (us) | 5.147 | 26.013 | 16.578 | 17.588 |

같은 그래프에서 Kruskal과 Prim이 구한 MST 전체 비용은 희소(1493), 밀집(271) 모두 일치했다.
MST의 전체 비용은 어떤 알고리즘으로 구해도 최솟값 하나로 정해지기 때문이다.
밀집 그래프의 비용이 훨씬 작은 이유는 간선이 많아 가중치가 작은 간선을 고를 선택지가 많기 때문이다
(간선 평균 가중치 희소 약 30.5, 밀집 약 5.5).

## 메모리 사용량 분석
- 인접 행렬 방식(Prim)은 50 x 50 배열이 항상 10004 Bytes라서 간선 수와 상관없이 총 11192 Bytes로
  희소와 밀집이 같았다.
- 인접 리스트 방식(Kruskal)은 간선 1개당 리스트 노드 2개(32 Bytes)와 정렬용 간선 배열 12 Bytes가
  필요해서 간선 수에 비례해 늘었다. 합계는 1396 + 44 x (간선 수)로 계산되고, 희소 5796 Bytes에서
  밀집 27796 Bytes로 약 4.8배 늘었다.
- 희소 그래프에서는 리스트(Kruskal)가 5796 Bytes로 행렬(Prim) 11192 Bytes의 약 절반이었다.
  밀집 그래프에서는 리스트가 27796 Bytes로 행렬보다 약 2.5배 많았다.
- 1396 + 44E = 11192 로 계산하면 간선이 약 223개를 넘을 때부터 이 조합에서는 행렬 쪽 메모리가 더 적다.
  희소(100개)는 그 아래, 밀집(600개)은 그 위라서 결과가 뒤집혔다.

## 실행시간 분석
- Kruskal은 간선을 모아서 정렬하므로 간선 수에 민감하다. 간선이 100개에서 600개로 6배 늘었을 때
  실행시간은 5.147us에서 26.013us로 약 5.1배 늘었다.
- Prim(인접 행렬)은 정점을 하나씩 트리에 넣으면서 50 x 50 행렬을 훑기 때문에(O(V^2)) 간선 수와
  거의 상관이 없다. 희소 16.578us, 밀집 17.588us로 약 1.06배밖에 차이 나지 않았다.
- 희소 그래프에서는 Kruskal이 약 3.2배 빨랐다. Kruskal은 간선 100개만 정렬하면 되지만, Prim은
  간선이 거의 없는 행렬(대부분 0)도 끝까지 확인해야 하기 때문이다.
- 밀집 그래프에서는 Prim이 약 1.5배 빨랐다. Kruskal이 정렬해야 할 간선이 600개로 늘었기 때문이다.
- 두 알고리즘의 속도가 뒤바뀌는 지점은 간선 100개와 600개 사이 어딘가이다. 이번에는 두 지점만
  측정했기 때문에 정확한 교차점은 알 수 없다.

## 알고리즘과 표현 방법의 특성 차이
- Kruskal은 간선 중심 알고리즘이다. 간선을 가중치 순으로 정렬한 뒤 Union-Find로 사이클이 생기는지
  확인하며 고른다. 시간은 간선 수에 따라 정해지므로(정렬 O(E log E)) 간선을 순서대로 모으기 쉬운
  인접 리스트와 잘 맞고, 간선이 적을수록 유리하다.
- Prim은 정점 중심 알고리즘이다. 정점이 50개라 반복 횟수가 정해져 있고, 행렬 구현에서는 간선이 몇 개든
  V x V 칸을 확인한다. 간선이 많아질수록 확인한 칸 중 실제 간선의 비율이 늘어나 상대적으로 효율이 좋아진다.

## 그래프 밀도의 영향
- 간선이 적은 희소 그래프에서는 리스트 + Kruskal이 메모리와 시간 모두 유리했다.
- 간선이 많은 밀집 그래프에서는 행렬 + Prim이 메모리와 시간 모두 유리했다.
- 즉 그래프의 밀도가 높아질수록 간선 수에 비례하는 방식(리스트, Kruskal)의 비용은 커지고,
  정점 수로 정해지는 방식(행렬, Prim)의 비용은 그대로라서 순위가 뒤바뀌었다.

## 한계
- 이번 비교는 "인접 리스트 + Kruskal"과 "인접 행렬 + Prim"이라는 조합끼리의 비교라서, 시간 차이가
  알고리즘 때문인지 그래프 표현 방법 때문인지 완전히 분리해서 말할 수는 없다.
- 그래프 하나(seed 하나), 컴파일러 최적화를 끈 환경에서 측정한 결과이므로 그래프나 환경에 따라
  수치는 달라질 수 있다.
