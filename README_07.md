# 과제-07: 인접 행렬과 인접 리스트의 성능 비교

## 실험 환경
- 정점 100개의 무방향 단순 그래프 (자기 루프, 중복 간선 없음)
- 희소 그래프: 간선 100개 / 밀집 그래프: 간선 4,000개
- 같은 그래프를 인접 행렬과 인접 리스트로 각각 표현했고, 같은 정점 쌍으로 연산을 수행했다.
- Seed: 1791958235
- sizeof(ListNode) = 16, sizeof(AdjList) = 816, sizeof(AdjMatrix) = 40004 (64비트 환경)

## 비교 횟수 기준

| 연산 | 인접 행렬 | 인접 리스트 |
|---|---|---|
| 연결 여부 확인 | matrix[u][v] 확인 1회 | u의 리스트를 v를 찾을 때까지(없으면 끝까지) 확인한 노드 수 |
| 인접 정점 출력 | matrix[u][0~99] 전부 확인 100회 | u의 리스트 노드 수 |
| 간선 삽입 | 존재 여부 확인 1회 | 존재 여부 확인을 위해 u의 리스트를 끝까지 확인한 노드 수 (삽입은 맨 앞이라 추가 비교 없음) |
| 간선 삭제 | 존재 여부 확인 1회 | u의 리스트에서 v를 찾은 노드 수 + v의 리스트에서 u를 찾은 노드 수 |

메모리는 행렬은 sizeof(AdjMatrix), 리스트는 sizeof(AdjList) + 노드 수 × sizeof(ListNode)로 계산했다.
난수 생성에 쓴 임시 배열은 제외했다.

- 밀집: 삽입 (57,41), 삭제 (5,20), 연결 확인 (5,76), 인접 정점 출력 35번 정점

## 희소 그래프 분석
희소 그래프는 간선이 100개라 정점 하나당 평균 이웃이 2개뿐이다. 인접 행렬은 간선이 적어도
100 x 100 공간을 그대로 쓰기 때문에 40004 Bytes였고, 인접 리스트는 간선 수에 비례해 4016 Bytes만
사용해서 약 10배 적었다. 인접 정점을 찾을 때도 행렬은 한 행 전체인 100칸을 확인해야 했지만 리스트는
실제 이웃 2개만 확인하면 되어 100회 대 2회로 차이가 컸다. 연결 확인은 행렬이 1회, 리스트도 이웃이
거의 없어 1회로 같았고, 삽입과 삭제는 리스트가 2~3회로 행렬보다 조금 많았지만 차이가 작았다.
즉 희소 그래프에서는 리스트가 메모리와 인접 정점 탐색 모두 유리했다.

## 밀집 그래프 분석
밀집 그래프는 간선이 4000개라 정점당 평균 이웃이 약 80개이다. 행렬의 메모리는 간선 수와 상관없이
40004 Bytes로 그대로였지만, 리스트는 노드가 8000개(무방향이라 간선당 2개)로 늘어 128816 Bytes가
되어 행렬보다 약 3.2배 많이 사용했다. 연산 비용도 뒤집혔다. 연결 확인은 행렬이 1회인데 리스트는
69회를 확인해야 했고, 삽입은 74회, 삭제는 44회로 행렬(각 1회)보다 훨씬 많았다. 인접 정점 출력은 행렬
100회 대 리스트 72회로 차이가 거의 없어졌다. 이웃이 많아질수록 리스트가 훑어야 하는 노드 수도
그만큼 늘어나기 때문이다. 연결 확인에서 선택된 두 정점이 연결되어 있지 않아 리스트가 끝까지
훑는 최악에 가까운 경우였다는 점도 감안해야 한다.

## 어떤 경우에 무엇을 쓸 것인가
- 행렬의 비용(연결 확인 1회, 삽입·삭제 1회, 인접 정점 100회)은 그래프의 밀도와 무관하게 일정했다.
  리스트의 비용은 정점의 이웃 수에 비례해서 증가했다.
- 메모리는 리스트 노드가 간선당 32 Bytes(노드 2개)이므로 (40004 - 816) / 32 = 약 1225개 간선을
  넘으면 리스트가 행렬보다 더 많이 사용한다. 이번 밀집 그래프(4000개)는 이 기준을 넘었다.
- 간선이 적고 인접 정점을 자주 순회하는 그래프는 인접 리스트가 적절하다.
- 간선이 많고 두 정점의 연결 여부를 자주 확인하거나 간선 삽입·삭제가 잦은 그래프는 인접 행렬이 적절하다.
