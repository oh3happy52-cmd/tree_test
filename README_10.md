# 과제-10: 정렬 알고리즘의 성능 및 안정성 비교

## 실험 환경
- 데이터: (key1, key2) 10,000개, 각 키는 0~1,000,000 난수. key1 기준 오름차순 정렬
- 각 데이터에 원래 입력 순서(order)를 따로 저장했다. 안정성 검증에만 쓰고 정렬 기준에는 쓰지 않았다.
- 정렬: 선택, 버블, 버블(조기 종료), 삽입(`>`), 삽입(`>=`)
- 모든 정렬에 같은 원본의 복사본을 입력했다. Seed: 20261026
- 비교 횟수: 두 데이터의 key1을 비교할 때마다 1회 (반복문 조건 제외)
- 이동 횟수: 데이터 전체를 복사·대입할 때마다 1회 (교환은 3회). 삽입 정렬은 임시 저장, 한 칸 이동, 최종 대입을 각각 센다.
- 선택 정렬은 최솟값이 이미 제자리면 교환하지 않는다.
- 정렬된/역순 데이터를 만들 때 쓴 `qsort`와 데이터 복사는 횟수에 포함하지 않았다.

## 1. 무작위 데이터 100회 결과
100회 모두 정렬 결과가 올바랐다.

| 정렬 | 총 비교 | 평균 비교 | 평균 이동 |
|---|---|---|---|
| 선택 | 4,999,500,000 | 49,995,000.0 | 29,970.2 |
| 버블 | 4,999,500,000 | 49,995,000.0 | 75,065,041.7 |
| 버블(조기 종료) | 4,998,364,963 | 49,983,649.6 | 75,065,041.7 |
| 삽입 `>` | 2,503,167,081 | 25,031,670.8 | 25,041,678.6 |
| 삽입 `>=` | 2,503,172,091 | 25,031,720.9 | 25,041,728.7 |

**일반 버블 vs 조기 종료 버블**: 평균 비교가 약 11,350회(0.023%) 줄었을 뿐이다. 무작위 데이터는 거의 끝까지 교환이 일어나서 조기 종료가 마지막 몇 번의 순회에서만 작동했다. 이동 횟수는 같다. 교환 자체는 줄지 않기 때문이다.

## 2. 안정성 검증

**검증 방법**: 정렬 후 인접한 두 데이터의 key1이 같은데 order가 거꾸로면 위반으로 세었다. 위반이 0이면 안정이다.

**입력 데이터**
- 과제 본문의 4개 데이터 (527,100) (527,200) (125,300) (892,400)
- 중복 키 데이터 1,000개 (key1을 0~49로 제한). 무작위 10,000개는 같은 키가 거의 없어서 따로 만들었다.

**결과**

| 정렬 | 작은 예시에서 (527,100), (527,200)의 순서 | 중복 키 1,000개 위반 수 | 판정 |
|---|---|---|---|
| 선택 | 뒤바뀜 | 320 | 불안정 |
| 버블 | 유지 | 0 | 안정 |
| 삽입 `>` | 유지 | 0 | 안정 |
| 삽입 `>=` | 뒤바뀜 | 950 | 불안정 |

**원인**
- 선택 정렬: 최솟값을 맨 앞과 **멀리 떨어진 채로 교환**한다. (125,300)을 앞으로 보내려고 (527,100)과 교환하면 (527,100)이 (527,200) 뒤로 밀린다.
- 버블 정렬: 인접한 두 데이터만 `>`일 때 교환한다. 같은 키는 교환하지 않아서 서로를 앞지르지 못한다.
- 삽입 정렬 `>`: 같은 키를 만나면 멈추고 그 뒤에 끼운다. 순서가 유지된다.
- 삽입 정렬 `>=`: 같은 키도 밀어내고 앞에 끼운다. 같은 키 그룹의 순서가 전부 뒤집힌다.

**`>`와 `>=`의 차이**: 정렬 결과(key1 순서)는 둘 다 맞지만 안정성이 다르다. `>=`는 같은 키도 한 칸 더 밀어서 비교와 이동이 조금 더 많다. 안정 정렬이 필요하면 `>`를 써야 한다.

## 3. 입력 상태별 결과 (비교 / 이동)

| 정렬 | 이미 정렬 | 역순 | 일부 정렬 |
|---|---|---|---|
| 선택 | 49,995,000 / 0 | 49,995,000 / 15,072 | 49,995,000 / 1,509 |
| 버블 | 49,995,000 / 0 | 49,995,000 / 149,984,856 | 49,995,000 / 9,387,447 |
| 버블(조기 종료) | **9,999** / 0 | 49,995,000 / 149,984,856 | 49,991,084 / 9,387,447 |
| 삽입 `>` | **9,999** / 19,998 | 49,995,000 / 50,014,950 | **3,139,148** / 3,149,147 |
| 삽입 `>=` | 10,047 / 20,046 | 49,995,000 / 50,014,998 | 3,139,196 / 3,149,195 |

**부분 정렬 데이터 생성 방법**: 정렬된 데이터에서 무작위로 고른 두 위치를 서로 교환하는 작업을 500번(전체의 5%) 반복했다. 그 결과 10,000개 중 954개만 제자리가 달라졌다. 생성 방법은 인공지능(Claude)에게 여러 방법(일부 위치 교환, 구간만 섞기, 소수 교란)을 조사한 뒤, 흐트러진 정도를 숫자로 설명할 수 있는 위치 교환 방식을 골랐다.

## 4. 분석: 왜 이런 차이가 났는가
- **선택 정렬**: 남은 구간을 항상 전부 훑어서 비교가 언제나 n(n−1)/2 = 49,995,000이다. 입력 상태와 무관하다. 교환은 많아야 n−1번이라 이동이 가장 적다. 정렬된 데이터는 교환이 0번이다.
- **버블 정렬**: 이동 횟수는 역전 쌍(앞이 뒤보다 큰 쌍)의 개수 ×3이다. 무작위는 평균 약 2,500만 쌍이라 이동이 약 7,500만이고, 역순은 모든 쌍이 역전이라 약 1억 5천만이다. 이동이 가장 많은 정렬이다.
- **조기 종료**: 완전히 정렬된 데이터에서만 크게 효과가 있다(49,995,000 → 9,999). 부분 정렬 데이터에서는 거의 줄지 않았다(49,991,084). 버블 정렬은 작은 값을 한 순회에 한 칸씩만 앞으로 보내서, 멀리 떨어진 값이 하나만 있어도 순회를 9,911번이나 해야 했기 때문이다.
- **삽입 정렬**: 비교는 대략 역전 쌍 + (n−1)이다. 그래서 정렬된 데이터에서 가장 빠르고(9,999), 부분 정렬 데이터는 무작위의 약 12.5%(3,139,148)이며, 역순에서 가장 느리다(49,995,000). 입력이 정렬에 가까울수록 유리하다.
- **정리**: 정렬된 상태에 가까운 데이터에는 삽입 정렬이 유리하고, 이동 횟수를 줄이고 싶으면 선택 정렬이 유리하다. `>`와 `>=`는 성능을 거의 바꾸지 않고 **안정성**을 바꾼다.

## 한계
- 시드 하나로 만든 데이터 한 세트로 측정했다. 정렬된/역순/부분 정렬 데이터도 각각 한 번씩만 측정해서 데이터에 따라 숫자가 조금 달라질 수 있다.
- 부분 정렬 데이터는 5%만 흐트러뜨린 경우만 확인했다. 흐트러뜨린 정도를 바꾸면 결과가 달라질 수 있다.
