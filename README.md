# 과제-05: 순차 탐색과 이진 탐색 트리 탐색의 비교

# 측정 결과

| 항목 | 값 |
|---|---|
| 순차 탐색 총 비교 횟수 | 4820 |
| 순차 탐색 평균 비교 횟수 | 96.40 |
| BST 탐색 총 비교 횟수 | 356 |
| BST 탐색 평균 비교 횟수 | 7.12 |
| BST 생성 시 총 비교 횟수 | 595 |

# 성능 차이 분석

순차 탐색은 평균 96.40회, BST 탐색은 평균 7.12회로, BST가 약 13배 더 적은 비교로 탐색에 성공했다.
이는 BST가 매 비교마다 탐색 범위를 절반씩 줄여나가는 반면, 순차 탐색은 값을 찾을 때까지
배열을 처음부터 순서대로 훑어야 하기 때문이다.

# BST 생성 비용을 고려한 분석

BST를 생성하는 데 595회의 비교가 추가로 발생했다. 이를 50회 탐색 비용(356회)에 더하면
총 951회로, 순차 탐색만의 총 비용(4820회)보다 여전히 훨씬 적다. 즉 데이터를 한 번만 저장하고
여러 번 탐색할수록 BST 생성 비용은 금방 상쇄되고, 전체적으로 BST 방식이 유리하다.

# 트리 구조에 따른 성능 변화

이번 실험은 데이터를 랜덤한 순서로 삽입했기 때문에 비교적 균형 잡힌 트리가 만들어져
좋은 효율을 보였다. 그러나 만약 데이터가 이미 정렬된 순서로 삽입되었다면
BST는 한쪽으로만 뻗어나가는 편향 트리(연결 리스트와 동일한 구조)가 되어, 탐색 성능이
순차 탐색과 같은 수준으로 저하되었을 것이다. 따라서 BST의 성능은 삽입 순서(트리의 균형도)에
크게 좌우된다.
